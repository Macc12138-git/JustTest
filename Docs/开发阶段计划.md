# JustTest 开发阶段计划

## 1. 当前开发目标

第一阶段只制作 2D 横版战斗原型，优先验证以下闭环：

```text
高速移动和翻滚
→ 当前武器普通攻击与技能
→ 技能对敌人直接施加状态
→ 备用武器进入 QTE 可选状态
→ 数字键执行 QTE
→ 所选武器成为当前武器
```

暂不开发局外成长、程序化地图、正式美术、存档、商店和剧情系统。

## 2. 工程基线

### 2.1 开发场景

- `Assets/Game/Scenes/CombatSandbox.unity` 是战斗原型的开发源场景。
- `Assets/Scenes/MainGame.unity` 和 `Assets/Scenes/SampleScene.unity` 暂时保留，不承载新战斗逻辑。
- `CombatSandbox` 位于构建场景列表首位。

### 2.2 程序集

- `JustTest.Game.Runtime`：承载所有游戏运行时代码。
- `JustTest.Game.Tests.EditMode`：承载不依赖实际场景运行的规则测试。
- 原型稳定前不继续拆分更多运行时程序集，避免增加不必要的依赖管理成本。

### 2.3 输入方案

- 第一版只支持键盘。
- 使用现有 `UnityEngine.Input`，暂不引入新版 Input System。
- 输入读取与角色行为分离，后续更换输入系统时不修改战斗规则代码。

### 2.4 Layer 约定

| Layer | 用途 |
|---|---|
| `Player` | 玩家实体与玩家物理碰撞体 |
| `Enemy` | 敌人实体与敌人物理碰撞体 |
| `Ground` | 实体地面和墙体 |
| `OneWayPlatform` | 可下穿的单向平台 |
| `PlayerHitbox` | 玩家攻击判定 |
| `EnemyHitbox` | 敌人攻击判定 |
| `Pickup` | 生命和能量恢复物 |

碰撞矩阵将在实际建立玩家、敌人和攻击判定时配置，避免在没有组件验证前提前屏蔽必要碰撞。

## 3. 代码与资源结构

```text
Assets/Game/
├── Art
├── Audio
├── Data
├── Prefabs
├── Runtime
│   ├── Core
│   ├── Input
│   ├── Player
│   ├── Combat
│   ├── Weapons
│   ├── Enemies
│   ├── Run
│   └── UI
├── Scenes
└── Tests/EditMode
```

- `Data` 保存武器、攻击、敌人和升级的 ScriptableObject 配置。
- `Runtime` 只保存运行时代码，不混入场景或美术资产。
- `Prefabs` 保存玩家、武器、敌人、攻击判定和恢复物预制体。
- 原型使用简单色块和临时资源，不提前建立正式美术管线。

## 4. 初步开发批次

### 批次一：玩家移动闭环

实现内容：

- 键盘输入快照和输入缓存。
- 地面移动、快速转向和空中横向控制。
- 单次跳跃、可变跳高、0.10 秒土狼时间和 0.10 秒跳跃缓存。
- `S + Space` 下穿单向平台。
- 地面翻滚、方向选择、动作时长、无敌窗口接口和恢复间隔。
- 正交摄像机跟随和基础灰盒平台。

完成条件：玩家可以在 `CombatSandbox` 中稳定移动、跳跃、下穿平台和翻滚，操作逻辑不依赖正式动画。

实施状态：已于 2026-07-23 完成。

- 已建立输入、移动、跳跃、地面检测、单向平台、翻滚、摄像机和沙盒重置组件。
- 所有操作参数由 `Assets/Game/Data/Player` 下的配置资产提供。
- Inspector 字段使用私有序列化字段，对外仅保留只读状态和必要控制接口。
- EditMode 规则测试共 7 项，全部通过。
- 已在 `CombatSandbox` 中完成实际键盘操作验证。

### 批次二：通用战斗内核

实现内容：

- `Hitbox`、`Hurtbox` 和单次攻击命中去重。
- 生命、伤害、硬直、击退、无敌和死亡。
- 攻击阶段、动作锁定、连击输入缓存和翻滚取消窗口。
- 共享角色能量、普通攻击命中回复和自动回复。
- 敌人状态事件和 QTE 一次性消费模型。
- 攻击范围、状态和伤害事件调试显示。

完成条件：玩家可以攻击训练目标，伤害、能量、受击无敌和每次攻击只命中一次的规则能够独立验证。

### 批次三：首个纵向战斗切片

实现内容：

- 三个独立武器槽和默认初级单手剑规则。
- 单手剑与双匕首的基础地面攻击、空中攻击和技能。
- 近战追击者的追击、预警、攻击、受击和死亡。
- 备用武器 QTE 检查、目标锁定、选择窗口和数字键选择。
- 最小武器槽、生命和能量 UI。

完成条件：完整运行以下流程：

```text
单手剑挑空斩
→ 敌人进入击飞状态
→ 备用双匕首高亮
→ 玩家按对应数字键
→ 执行双匕首空中追猎
→ 双匕首成为当前武器
```

## 5. 后续开发顺序

首个纵向切片稳定后，依次进行：

1. 加入重锤和完整三武器 QTE 循环。
2. 支持重复武器槽、双备用武器同时高亮和 QTE 状态取消。
3. 加入远程弩手、重装冲锋者和精英守卫。
4. 建立三个战斗区域、波次、恢复物和快速重开。
5. 加入三次升级选择与 14 个升级。
6. 完善 HUD、命中停顿、慢动作、镜头、音效和临时特效。

## 6. 实现约束

- 武器类型、技能、攻击和 QTE 条件必须通过配置扩展，不能写死为三种测试武器。
- 每个武器槽保存独立运行时状态，生命和能量由角色共享。
- 技能直接施加状态，不建立状态累计条。
- QTE 使用一次性状态事件，成功、失败或超时后都不能重复消费。
- 战斗规则时序由代码和配置控制，动画只负责表现。
- 每个开发批次结束后检查编译、场景保存状态、关键操作流程和 Git 变更范围。

本文档中的完成条件用于控制开发批次，不作为正式试玩验收方案。
